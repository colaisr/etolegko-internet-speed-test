## F2 — Создатель кампании

> **Реализовано** (2026-11-19, change `campaign-creator`). Как работает сейчас: [`ProductDocs/01-campaign-creator.md`](../ProductDocs/01-campaign-creator.md).

**Ценность:** стандартная 2-поточная кампания без ручной сборки в Keitaro.

| AC | Критерий |
| --- | --- |
| F2.1 | Поля: имя, geo (ISO-2), оффер (поиск) + превью шаблона |
| F2.2 | Create создаёт в Keitaro: geo→Google, остальное→1 оффер 100%, domain/group/source |
| F2.3 | На успехе: URL, keitaro id, read-only domain/group/source |
| F2.4 | Запись в SQLite; переход в редактор с **авто-Fetch** |
| F2.5 | Ошибка API → нет битой кампании (rollback) |
| F2.6 | Невалидный geo/offer → ошибка на форме, без вызова create |

**Границы:** иной URL кроме Google, >2 потоков — не в MVP.

## F3 — Загрузка потоков (Fetch)

**Ценность:** локальная картина = Keitaro до начала черновика.

| AC | Критерий |
| --- | --- |
| F3.1 | Fetch подтягивает потоки кампании |
| F3.2 | Оффер-поток: таблица id, имя (если есть), вес %, pin, статус |
| F3.3 | Служебный поток: одна строка без деталей редиректа |
| F3.4 | После Create автоматический Fetch (без лишнего клика) |
| F3.5 | Повторный Fetch по кнопке не затирает незапушенный черновик без правил merge (см. F7) |

---

## F4 — Операции с офферами (симулятор)

**Ценность:** играть с миксом без Keitaro.

| AC | Критерий |
| --- | --- |
| F4.1 | **Add:** поиск оффера, добавление, пересчёт весов, поток жёлтый |
| F4.2 | **Remove:** 0%, removed, пересчёт, жёлтый |
| F4.3 | **Bring back:** active + пересчёт, жёлтый |
| F4.4 | **Pin:** зафиксированный %; пересчёт только unpinned; сумма 100% |
| F4.5 | **Largest remainder:** целые %, сумма ровно 100 |
| F4.6 | До Push Keitaro **не** меняется (проверка: обновить Keitaro admin / повторный Fetch с сервера) |

**Эталонные примеры:**

- 3 active → 34+33+33 или 33+33+34
- pin 25% + 2 active → 25+38+37 (или эквивалент по алгоритму)

## F5 — Публикация и отмена

**Ценность:** двухшаговое выкладывание; откат бесплатен.

| AC | Критерий |
| --- | --- |
| F5.1 | **Cancel** откатывает локально к последнему успешному Push |
| F5.2 | **Push** применяет состав и веса в Keitaro |
| F5.3 | После успешного Push: поток белый, бейдж «Синхронно», обновлён слепок в SQLite |
| F5.4 | Ошибка Push: черновик сохраняется, повтор возможен |

---

## F6 — Валидация и diff (обязательная ценность)

**Ценность:** байер подписывает только осмысленные изменения.

| AC | Критерий |
| --- | --- |
| F6.1 | Push disabled если sum ≠ 100% или нет active офферов |
| F6.2 | Рядом с таблицей отображается сумма %; при ошибке — текст причины |
| F6.3 | Push открывает modal **diff**: добавить / убрать / изменить веса |
| F6.4 | Diff соответствует фактическому delta (ручная проверка сценария F4) |
| F6.5 | UI по [`design-system.md`](../ProjectDocs/design/design-system.md) |

---

## F7 — Рассинхрон с Keitaro

**Ценность:** не врать, если в трекере уже правили.

| AC | Критерий |
| --- | --- |
| F7.1 | Оффер есть локально, нет в Keitaro после Fetch → **removed** |
| F7.2 | removed можно **bring back** → push снова |
| F7.3 | Локальный черновик (жёлтый) согласуется с Fetch: пропавшие в Keitaro → removed, не silent delete |
