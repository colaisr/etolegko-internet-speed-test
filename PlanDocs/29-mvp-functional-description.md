# MVP — функциональное описание (фаза B)

> **Статус:** актуален (2026-11-19, фаза B закрыта). Читать вместе с [`00-product-overview.md`](00-product-overview.md). Детали по фичам: [`01`](01-campaign-creator.md), [`02`](02-stream-offer-editor.md).

## 1. Общая логика продукта для байера

| Зона | Что делает байер | Где «симулятор» | Когда трогается Keitaro |
| --- | --- | --- | --- |
| **Создаватор** | Заводит новую кампанию по шаблону | После создания — дальше работа в редакторе | **Сразу** при Create (кампания + потоки) |
| **Редактор** | Крутит офферы и веса | **Весь** цикл до Push | Только на **Push** |

Главный опыт ценности — **редактор**. Создаватор сокращает путь **к** этой песочнице.

## 2. Навигация MVP (верхний уровень)

Без полного каталога кампаний Keitaro:

1. **Старт** — «Создать кампанию» или «Открыть по ID» (keitaro campaign id или локальный id после create).
2. **Экран создавателя** — только для новых.
3. **Экран редактора** — для существующей: шапка кампании + потоки + панель оффер-потока.

**Решение product (2026-11-19):** на старте MVP два входа в редактор: (1) автопереход сразу после Create; (2) поле **«ID кампании в Keitaro»** + опционально выпадающий список **«Недавние в Legko»** (кампании из SQLite за эту установку). Отдельного «каталога всех кампаний Keitaro» нет — байер обычно помнит свою связку или id из Keitaro; недавние снимают боль «я только что создал, куда жать». Обоснование: §10 в этом файле.

## 3. Модуль: создаватель кампании

Подробно — [`01-campaign-creator.md`](01-campaign-creator.md).

**Ценность:** шаблон за минуту → сразу в песочницу сплита.

**Пользователь может:**

| Действие | Результат для байера |
| --- | --- |
| Ввести имя, geo, выбрать/найти оффер | Видит превью: «поток 1: {geo}→Google; поток 2: остальное→оффер X» |
| Нажать Create | Кампия в Keitaro + запись в SQLite + **URL для трафика** + показ domain/group/source |
| Перейти в редактор | Попадает в симулятор сплита с одним оффером 100% |

**Система обязана:** откатить Keitaro, если создание оборвалось на середине; не оставлять «висячую» кампию без потоков.

## 4. Модуль: редактор (симулятор сплита)

Подробно — [`02-stream-offer-editor.md`](02-stream-offer-editor.md).

**Ценность:** настроить микс и веса, **увидеть будущее**, отменить или выложить.

### 4.1 Шапка кампании

| Элемент | Зачем байеру |
| --- | --- |
| Имя, Keitaro ID, URL | Контекст |
| **Статус** «Синхронно» / «Есть черновик» / «Нужен Fetch» | Не держать в голове жёлтые потоки |
| Кнопка **Fetch Streams** | Подтянуть правду из Keitaro и слить с локальной |

### 4.2 Блок потоков

- **Служебный поток** — одна строка: «Служебный поток (geo и др.) — не редактируется».
- **Оффер-поток** — рабочая область; индикатор **белый/жёлтый**.

### 4.3 Таблица офферов (сердце симулятора)

Колонки (логически): оффер (имя + id), вес %, pin, статус (active/removed), действия.

| Операция | Что видит байер | Keitaro |
| --- | --- | --- |
| **Add** | Поиск оффера, новая строка, **пересчёт %**, поток жёлтый | Без изменений |
| **Remove** | Строка серая, 0%, жёлтый | Без изменений |
| **Bring back** | Снова в сплите, жёлтый | Без изменений |
| **Pin %** | Зафиксированный вес; остальные пересчитаны | Без изменений |
| **Cancel** | Всё как после последнего Push, белый | Без изменений |
| **Push** | Сначала **diff**, подтверждение; потом белый | **Обновлён** |

### 4.4 Push-гейт (обязательная ценность)

Перед Push:

1. Если сумма активных весов ≠ 100% или нет ни одного активного оффера — **Push недоступен**, понятная причина.
2. Модальное **diff**: что добавится, удалится, какие веса изменятся в Keitaro.
3. Подтверждение → вызов API → успех или ошибка с сохранением черновика.

Байер понимает: «вот что я сейчас реально включу в трекер».

### 4.5 Fetch при чужих правках

Байер нажимает Fetch после правок в Keitaro:

- Совпадающие офферы — как были.
- Исчезнувшие в Keitaro — **removed** в таблице (не исчезают из UI).
- Бейдж кампании может стать «Нужен Fetch» до нажатия, если обёртка знает о возможном drift (упрощённо: после ошибки push / по желанию показывать подсказку «давно не Fetch» — опционально в MVP).

## 5. Пересчёт весов (поведение, которое байер ощущает)

| Ситуация | Ожидание байера |
| --- | --- |
| 4 активных оффера, без pin | Каждый 25% |
| Добавил пятый | Все по 20% |
| Убрал одного (remove) | Остальные делят 100% поровну |
| Один pin 25%, три других | 25 + три по 25% |
| Pin 25%, добавил четвёртый | 25% + три по 25% |
| Только removed | Push заблокирован |

## 6. Пустые и ошибочные состояния

| Ситуация | Что показываем | Ценность |
| --- | --- | --- |
| Первый вход в редактор без Fetch | «Нажмите Fetch, чтобы загрузить потоки» | Ясный старт |
| Keitaro недоступен | Ошибка, повторить; локальный черновик не теряется | Не потерять работу |
| Push упал | Черновик жёлтый остаётся | Можно исправить и повторить |
| Все офферы removed | Push недоступен | Не выкатить пустую ротацию |
| Поиск оффера — пусто | «Не найдено, проверьте ID» | Меньше мусора в миксе |

## 7. Сквозной сценарий «день байера»

1. **Create** новый ленд → URL → **Редактор**.
2. **Fetch** → один оффер 100%.
3. **Add** два оффера → вижу 33/33/34 или равные трети по правилам пересчёта (равномерно до целых — уточнить в фазе D округление).
4. **Pin** сильный на 40% → остальные подстроились.
5. Смотрю **diff** → **Push** → статус «Синхронно».
6. Коллега убрал оффер в Keitaro → я **Fetch** → **removed** → решаю bring back или оставить → **Push**.

## 10. Решения product (типовые паттерны для байера)

> Владелец не из арбитража — ниже зафиксированы ответы по аналогии с **draft/sandbox → publish** (Notion, Figma, CMS, Ads editing) и с логикой эталонного видео.

| # | Вопрос | Решение | Почему байеру так удобнее |
| --- | --- | --- | --- |
| 1 | Как открыть кампанию в редакторе | **Create → сразу редактор** + отдельный вход: **Keitaro campaign ID** + **«Недавние»** (SQLite) | После создания не ищет id; к вчерашней связке — один клик; чужую кампанию — по id из Keitaro (как в админке) |
| 2 | Domain / group / source | **Read-only из конфига** на Create и в шапке редактора; **без выбора в MVP** | В команде один боевой домен/группа; выбор — источник ошибок; смена — редко, через env/админ позже |
| 3 | Округление весов до 100% | **Largest remainder**: целые %, сумма ровно 100 | Байер видит целые числа, как в Keitaro; 33+33+34 при трёх офферах — норма рынка |
| 4 | Fetch после Create | **Авто-Fetch** при первом входе в редактор после Create; дальше **Fetch вручную** (явная кнопка) | Сразу видит таблицу; повторный Fetch — осознанно («подтянуть из Keitaro») |

### 10.1 Не делаем как «большие» Ad-платформы

Нет глобального campaign picker, нет прав по командам, нет preview трафика — это другой класс продуктов. Legko — **узкий симулятор сплита** для одного байера/одного инстанса тестового.
