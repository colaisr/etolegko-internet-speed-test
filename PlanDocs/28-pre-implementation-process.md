# Процесс до реализации (Legko)

> **Статус:** актуален (2026-11-19). Решение владельца: **роль project-manager в этом проекте не используется**. Планирование ведут владелец и агенты product / designer / developer; фиксация — в `PlanDocs/`.

## Зачем отдельный процесс

Сначала собираем **целостное видение продукта** (ценность + функционал + облик + архитектура), затем режем на этапы и OpenSpec changes. Реализация не начинается, пока не закрыта **точка готовности** в §6.

## Фазы (порядок обязателен)

### Фаза A — Product: ценность и детали

- Пройти MVP с опорой на [`00-product-overview.md`](00-product-overview.md).
- Закрыть открытые продуктовые вопросы, согласовать границы scope.
- **Результат:** владелец и product довольны формулировкой «зачем» и «что входит».

### Фаза B — Product: функциональное описание MVP

- Описать **весь** функционал будущего MVP простым языком, **постоянно привязывая к ценности** для байера (не список кнопок).
- Дополнить / уточнить разделы `01`, `02`, при необходимости новые файлы PlanDocs.
- **Точка остановки владельца:** «всё зафиксировано у продукта» — после этого фаза B считается завершённой; правки только осознанные.

### Фаза C — Designer: облик

- Кратко определить: экраны, иерархия, статусы (белый/жёлтый/серый), ключевые компоненты.
- Артефакты: `ProjectDocs/design/`, при необходимости прототипы в `artifacts/prototypes/`.
- **Результат:** дизайн-вердикт + ссылки на файлы; product подтверждает, что UI несёт ту же ценность.

### Фаза D — Product: разрез по фичам

- Собрать функционал из фаз A–B + ограничения из фазы C.
- Разбить на **фичи** с детальным описанием: сценарии, граничные случаи, **acceptance criteria** на фичу.
- Обновить [`25-mvp-plan.md`](25-mvp-plan.md) и индекс [`README.md`](README.md).

### Фаза E — Developer: стек и архитектура

- Выбрать стек (Python-бэкенд, UI), вписать функциональные блоки в **единый каркас**.
- Детализировать [`15-architecture.md`](15-architecture.md): модули, API, SQLite, интеграция Keitaro.
- **Результат:** PlanDocs описывают **планируемый продукт целиком** — готов к нарезке на OpenSpec.

### Фаза F — План работ и реализация

- Разбить на этапы (эпики E0… из `25`, затем OpenSpec changes).
- `/opsx:propose` → apply → verify → archive по [`openspec-gates.md`](../ProjectDocs/roles/openspec-gates.md).
- Статусы и приоритеты — **владелец + product в чате и PlanDocs**, не в отдельной task-системе.
