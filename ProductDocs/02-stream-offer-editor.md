# Редактор потоков и офферов

> **Обновлено:** 2026-11-19 · **Change:** stream-editor-resync (F7)  
> **Замысел:** [PlanDocs/02-stream-offer-editor.md](../PlanDocs/02-stream-offer-editor.md) · **Спеки:** `stream-editor-fetch`, `stream-editor-offer-ops`, `stream-editor-publish`

## 1. Что это и зачем

Редактор — **симулятор сплита**: байер видит потоки и меняет микс офферов **локально**, сверяясь с Keitaro через обновление снимка. **Push** выкладывает сплит в трекер после просмотра **diff**.

## 2. Как это работает сейчас

- **`/campaigns/{id}/editor`** — шапка (имя, Keitaro id, geo, status pill, URL с копированием), **Обновить из Keitaro**.
- После **create (F2)** потоки подтягиваются автоматически (`full_fetch`); если потоков нет — блок «Потоки ещё не загружены» и CTA обновления.
- **POST `/campaigns/{id}/fetch`**:
  - **без черновика** — полная перезагрузка потоков из Keitaro + новый опорный снимок;
  - **с черновиком (жёлтый)** — **merge**: служебные потоки обновляются; оффер-строки **не затираются**; оффер, который был в снимке и **пропал в Keitaro**, становится **removed**; локально добавленные (ещё не в снимке) **остаются**.
- **Служебный поток** — одна серая строка с lock (geo → Google), без деталей фильтра.
- **Оффер-поток** — таблица с Σ активных %, действиями F4 (добавить / убрать / вернуть / pin). Локальные правки → **жёлтый** поток (`has_draft`), бейдж **Черновик**. Pin/remove/restore обновляют таблицу **без перезагрузки** страницы (HTMX); поле «Закрепить %» сразу показывает превью Σ, если сумма ≠ 100%.
- **Отменить изменения** — откат к последнему снимку (Fetch/Push без черновика или после успешного Push).
- **Push / diff** — F5/F6: валидация Σ=100%, модалка diff, запись в Keitaro.

## 3. Кто что может

Один байер — полный доступ к экрану, Fetch, симулятору и Push при настроенном Keitaro API.

## 4. Правила и граничные случаи

- Удаление последнего active оффера допускается (Σ=0, Push disabled) — можно вернуть или добавить строку.
- При merge-Fetch опорный снимок **не** меняется (Cancel всё ещё к последней синхронизации).
- Pin — локальная метка; в Keitaro уходят только веса active-офферов.
